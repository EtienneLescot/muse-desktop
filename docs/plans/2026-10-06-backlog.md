## M2-05 — Handoff

- The preview is slow with thousands of untracked files, about 65 ms each. **Why deferred:** performance only; the result is right.
- Staging arrives unstaged. **Why deferred:** the question says so before the move; bytes are identical and the staged versions stay in the snapshot ref.
- A case-only rename is refused as a conflict on case-insensitive disks. **Why deferred:** refused before any write, no loss; committing the rename first works.
- Not exercised natively: a delete impossible on the target, an active turn only in the target, concurrent moves, the undo of a file modified in between. **Why deferred:** Rust tests cover these paths (`git.rs`, `claim_handoff`).
- Lossy clean filters (nbstripout) on a file changed on both sides drop the filtered bytes. **Why deferred:** git merge does the same.
- A merge-driver name containing `=` escapes `-c`. **Why deferred:** no such name seen; the fix (`--config-env`) is noted in `git.rs`.
- Two moves in the same millisecond would write the same snapshot ref. **Why deferred:** the folder claim refuses a second move of the same folder, so it takes two folders of one repository moved in the same millisecond.
