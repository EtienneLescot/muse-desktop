# muse-desktop — PART 1: Functional spec (V1/V2)

> Scope: a Tauri+React desktop client backed by the `muse serve` CLI (sidecar). A premium Meta Muse-branded equivalent of Codex Desktop / Claude Desktop. State proved by the code read: 1 host shared per workspace, multiplexed by `sessionId`, streaming through serialised 150/1000 ms polling, approvals through anti-replay choices, answerable input (`userInput/requested`), local persistence. Sources: `audit-local` (main.rs, msp.rs, useMuseSessions.ts, lib/persist|input|poll|env), `ref-codex`, `ref-claude`, `ref-antigravity`, `ref-opencode`, `ref-zed`. Everything not proved is marked **[GAP]**.

## 1. Vision & positioning

**V1 — A reliable local command centre.** `muse-desktop` = a premium Meta Muse shell around a single shared `muse serve`: 1 host per workspace (changing workspace kills/respawns the old one; `initialize` handshake then the `initialized` notify, without which every call fails `Not initialized`), sessions multiplexed by `sessionId`. Line-by-line JSON-RPC 2.0 transport (`split_lines`), UUIDv7 `commandId`, 120 s timeout. Streaming through polling over a buffer bounded at 2000 events (`poll_events/since`, `head` cursor): the `listen` push resolved but never fired in one environment [GAP: environment not identified], hence the same broadcast semantics on top of `invoke`. UI poll at 150 ms while streaming / 1000 ms idle (adaptive setTimeout, never setInterval), a single serialised chain (`poll.ts`: the periodic tick and the kick share a promise chain, the cursor only advances on success) + an immediate kick after send/answer/approve; running/stopped statuses derived from the `turn/*` kinds (`started/running/created/turn_start` vs `cancelled/completed/stopped/exited/host_exited/error/turn_end/idle`). Local `localStorage` persistence: sessions (without the running flag), an append-only log capped at 2000 entries per session (`open` blocks closed on reload), workspace, activeId, tombstones capped at 500 (durable deletion despite `restore_sessions` and late events). Packaging: `externalBin binaries/muse` + `resolve_sidecar()` (exe dir then `src-tauri/binaries/`, name suffixed by target triple, `.exe` on Windows); an explicit message if the binary is missing.

**Target — Premium Codex/Claude parity + the Antigravity doctrine.** Codex = an agent command centre: threads separated by project, switching without losing context, commented diff review + opening in an editor, integrated worktrees [ref-codex]. Claude = a unified directory of Skills/Connectors/Plugins, 1-click local MCP (`.mcpb`) + remote, versioned artefacts in a right-hand window, Projects/RAG, isolated cloud Cowork [ref-claude]. Antigravity = an agent control-plane IDE (plan/execute/verify over editor+terminal+browser), an async multi-workspace Manager Surface, "verify with Artifacts, not logs" (plans, task lists, walkthroughs + screenshots/recordings, delegate→review→comment→iterate) [ref-antigravity]. OpenCode/Zed = the reference for transport/config/permissions: `serve [--port --hostname --cors]` (default 4096/127.0.0.1, OpenAPI), a type-safe SDK, multi-agent threads + checkpoints + compaction, regex allow/deny/confirm permissions, Write/Ask/Minimal profiles, the ACP standard [ref-opencode/ref-zed].

**Premium Meta branding [total GAP].** No asset read (favicon only, placeholder icons, a generic productName, null CSP, BUILD_ID `2026-09-08-poll-transport` the only marker). No source for defining "premium vs Codex/Claude Desktop". V1: do not specify a charter, tone, logo or naming. A Figma/UX mockup is still to be decided [unresolved].

## 3. Functional domains, stories & acceptance

### 3.1 Conversations / threads / projects
- **US-1 (M-V1):** I create/list/resume sessions of the shared host, multiplexed by sessionId. **AC:** `start_session/restore_sessions/send_input/cancel/kill` through the sidecar as the only channel; `session/start` receives the global posture through the closed enum `allowAll|promptUnmatched|onRequest` and `session/setApprovalMode` reconciles an existing session; switching session with no loss of the persisted log (2000 entries); a durable tombstone (cap 500, late events and `restore` never resurrect); at boot outside Tauri (`backendMissing`) the local history stays visible with no misleading banners.
- **US-2 (M-V1):** I see the stream coalesced by `itemId`, sub-agents grouped by `agentId` in foldable `<details>`, `item_done` closes only its own item. **AC:** `output` chunks merged into the last *open* assistant entry (not merely the last one); `item/completed|updated` → `item_done` closes the exact `itemId`, the other items continue; `turn/completed` closes everything + `running=false`.
- **US-3 (S-V2):** I organise threads by project, with instructions, view/edit sharing (Team/Enterprise), Free capped at 5 projects, RAG ~10x [ref-claude Projects]. **AC:** project creation, attaching threads, view/edit sharing, a simulated quota of 5 on Free.
- **US-4 (S-V2):** I compact long threads (automatically at a token threshold + manual `/compact` + `New From Summary`) [ref-zed]. **AC:** compaction triggered at the threshold, the summary reopenable as a new thread. [GAP: muse token threshold unsourced.]
- **US-5 (S-V2):** a threads sidebar with concurrent multi-agents, ctrl-tab switching, an archivable history [ref-zed parallel-agents]. **AC:** ≥2 active threads visible, switching < §5.

### 3.2 Visible multi-agent orchestration + worktrees
State proved: sub-agents owned by sidecar orchestration, no direct IPC spawn; commands limited to start/restore/send/approve/answer/cancel_input/cancel/kill/setApprovalMode and deferred `item/readOutput` reading. Routing: `item/delta`→output/thinking/subagent_event (the lane chosen by a `(sessionId,itemId)→kind` table fed by `item/started`, scoped per session), `approval/requested`→tool_request, `userInput/requested`→input_request, `turn/*`→status. `reasoning`, `thinking`, `analysis` items and their summary variants are rendered in a dedicated thinking lane, persisted with the log and foldable in the thread. Tool items exposing `outputRef` keep only that reference in the log; the interface requests the bytes through `item/readOutput` in bounded blocks, without copying the whole output into the local history. Stable MSP schema 1.2.1 (sha c7ff6c5d): 33 methods including 8 control-only `subagent/*` (close/followupTask/interrupt/readResult/reopen/resume/sendMessage/stop), **no spawn/start method**, stable or experimental; the `subagent` item: objective/role, agentPath, depth (no max), childSessionId (drill-down through session/read|view/page), open controlStatus, result summary ≤512 chars / text ≤32 KiB; 0 hits for parallel/maxConcurrent/worktree/isolation (the only caps = view pagination 1-1000, session list max 200, context/output caps).
Isolation reference (official cookbook): concurrency ≈ cores-2 clamped to 4-8; extras ADMITTED and queued FIFO; a demo of 6 simultaneous; each writer child = a private git worktree under `.muse/worktrees/` on a detached HEAD (base_commit, base_ref HEAD, cleanup remove_if_clean), depth 1, committing on its own branch, the parent checkout intact; the cycle `operation_requested>prepared>lease_active>workspace_scope_activated`; the vocabulary = a model-tool plan `subagent_spawn(role,objective,worktree_isolation:true)` + wait/read/status; the CLI gate `muse --subagent-worktree-isolation` (without the flag = shared); a manual fallback `git worktree add -b taskN-branch`.
- **US-6 (M-V1):** I see each subagent (agentId, objective/role, depth, status, truncated result) grouped by agentId, deltas concatenated into its open entry. **AC:** 2 subagents interleaved with the assistant → 3 distinct entries, no chunk mixed; parsing JSON `{agent_id,text}` + fallback `/*id*/`/`id:` + plain text.
- **US-7 (S-V2):** I fan out through the parent turn (the prompt), not through MSP (no callable spawn endpoint). **AC:** N parallel requests → N children visible, a FIFO queue beyond cores-2 clamped to 4-8 [GAP: no official absolute N].
- **US-8 (S-V2):** every writer runs on a private `.muse/worktrees/` worktree with remove_if_clean cleanup. **AC:** parent checkout unchanged (HEAD hash identical before/after); its own branch per child. Sourced risks: the same checkout = overwrites/contaminated test state → 1 worktree+branch per agent + a file-level contract + deterministic validation, never direct integration on a protected branch [DZone]; minimise overlaps, otherwise 1 owner + another reviewing, compare diffs, record merge order [Warp].
- **US-9 (C-V2+):** automations = scheduled background instructions+skills, results reviewable and human review depending on the policy [ref-codex]; recurring/one-shot scheduled tasks (for example Mon/Wed 9am), threads reused [ref-claude/antigravity]. **AC:** schedule creation, triggering on time, workspace/project/model/policy context captured; `ask` goes through the review queue, `workspace`/`yolo` dispatch with no click and log the occurrence; `latest/skip` catch-up, idempotency and bounded retries. **Current limit:** the timer stays in the app and `completed` means `send_input` acknowledged, for want of a usable MSP end-of-turn event. [GAP: `workflow/*` has no schema line (spec 14410 open) → a native scheduler and workflow parallelism cannot be specified over MSP.]

### 3.4 Approvals / permissions
State proved: `approval/requested` → a choice panel (choiceId/label/decision/scope, toolName, summary `tool: rawArgs` truncated to 200); `approval/updated` replaces the choices and advances a compound command's `currentRequirementId`; `approve` requires requirementId + the same session (cross-session anti-replay; a stale token is rejected by the host with -32053, the error surfaced, never applied silently); multi-step decisions: `terminal=false` keeps the card and the token for the next step, `terminal=true` removes it (replay impossible). Codex rules: `prefix_rule` allow/prompt/forbidden, most-restrictive-wins, the allow-list `~/.codex/rules/default.rules`, Smart approvals, trust-gated, `approval_policy` on-request/never/granular, `approvals_reviewer` user/auto_review. Zed: regex allow/deny/confirm (default confirm, `sudo` forced to confirm), Write/Ask/Minimal profiles. OpenCode: `permission` allow/ask/deny, `--auto` approves everything not denied, wildcards, per agent, `ask`→approval.
- **US-14 (M-V1):** I approve/refuse a choice with a visible scope. **AC:** approve with no requirementId or cross-session → an error displayed, no effect; a terminal decision → panel removed + polling/stream resumes with no protocol system line; an intermediate decision → panel kept and updated on `approval/updated`; a refusal choice does not paint a false "resume" bridge; `cancel_session` sends `turn/interrupt{retract:false}` and keeps the conversation in a requested-stop state until the host's terminal status (`turn/completed`/`turn/retracted`). On a rejection or with no engine, the local state is released with an explicit cancellation status.
- **US-15 (S-V2):** a persistent per-command allowlist + allow/prompt/forbidden granularity + most-restrictive-wins + allow/deny for network/domains. **AC:** persistence after a restart, a conflict → the most restrictive wins.
- **US-16 (S-V2):** a configurable sandbox (default folder/branch + web search hidden; network/elevated requires permission; project/team rules) [ref-codex security]. **AC:** an out-of-scope attempt → a prompt; network without permission → denied. [GAP: muse's exact sandbox config (`--trust-workspace/--disable-sandbox`, `MUSE_ALLOW_UNSCOPED_READS=1 DANGEROUS`, `promptUnmatched→request_permission`) known only through brokkai/muse-acp — to confirm through `--help`.]
- **M0-06 global posture (wired on the client + host side):** the **Ask for approval** setting selects `onRequest` and leaves every `approval/requested` to the user; **Approve on my behalf** selects `promptUnmatched`, auto-decides choices whose scopes stay local to the workspace and keeps a question for network/elevation; **YOLO** selects `allowAll` and decides the first non-refused choice. The posture is persisted under `muse-desktop.authorization-mode.v1`, sent to `session/start` and reconciled mid-session through `session/setApprovalMode`, without bypassing `denied` choices or the anti-replay protections.

### 3.5 Answerable input

## 1. Target architecture

### 1.1. Principles

- `muse-desktop` = a desktop shell (Tauri + React) around a **single agent engine: `muse serve`**, embedded as a **sidecar**. No LLM engine in the client (`main.rs` L1-13: "No agentic logic lives here: spawn, frame relay, kill").
- The OpenCode reference: the same TUI + desktop pattern around a headless engine (`serve [--port --hostname --cors]`, default `127.0.0.1:4096`) + a type-safe SDK. Here: the `muse` sidecar + a home-made MSP client `MspClient` (`msp.rs` L138-143) — **[GAP: no known JS SDK, no HTTP port/contract proved in the code read]**.
- The **line-by-line MSP JSON-RPC 2.0** protocol (`msp.rs` L1-13: one frame per line, `serde_json` escapes internal `\n`), camelCase params (`sessionId`, `commandId`). Not ACP — ACP interop is out of scope for V1 **[GAP: framing proved by the code + a TS schema cited in a comment, a live handshake impossible in the sandbox without credentials — a documented hypothesis, not proved live]**.

### 1.2. Tauri sidecar

- Resolution: `resolve_sidecar()` (`main.rs` L227-258) builds `binaries/muse-<TAURI_ENV_TARGET_TRIPLE>` (+`.exe` on Windows), looks (1) next to `current_exe()` (the bundled `externalBin` layout), (2) in `CARGO_MANIFEST_DIR/binaries/` (dev); otherwise an error listing the paths tried + a pointer to `src-tauri/binaries/README.md`. `spawn_sidecar()` (L260-277) passes the absolute path to `shell().sidecar()` (join no-op), `.args(["serve"])`, `.current_dir(root)` — **the sandbox is fixed at spawn through the cwd**.
- Windows first launch: `SidecarErrorPanel` keeps the bounded message and the paths probed, then presents contextual guidance based on the error's clues (binary, WSL, Muse CLI, authentication, accessible folder) with Retry and Choose a folder actions. That guidance installs nothing and does not claim to validate WSL/auth; validation on a clean machine and on non-default distributions **[GAP]**.
- State proved: **a single shared host, multiplexed by `sessionId`** (`AppState.host: Mutex<Option<Host>>`, L83-97); **one host per workspace — changing workspace kills/respawns the old one** (`ensure_host()`, L141-211: compares `h.workspace == *root`, otherwise `shutdown()` then respawn). Creation serialised by `host_mutex: tokio::Mutex<()>` (L94): two concurrent `start_session`s do not spawn two hosts.
- A two-step handshake (L185-200, "proven against the real binary"): `request("initialize", {clientInfo:{name:"muse_desktop", version:"0.1.0"}})` then `notify("initialized", Null)` — without the notify, every later call fails `Not initialized`. The response is validated before the notify: `serverInfo.name=muse`, a non-empty version, `schema.version=1` and a `sha256:*` fingerprint; an incompatibility stops the sidecar with a usable error and its last 20 stderr lines (`stderr_tail`, `tail_of()`).
- The session-lifecycle IPC surface (`main()` `invoke_handler!`): the commands `start_session / set_approval_mode / restore_sessions / send_input / unqueue_turn / approve / answer_input / cancel_input / cancel_session / kill_session / set_workspace / read_session_history / page_session_history / list_pending_requests / poll_events`. That list is a subset oriented to the session lifecycle; the complete IPC surface also includes `check_scope`, `list_models`, `set_model`, `compact_session` and the `subagent_*` commands. Front-end events: `output, subagent_event, tool_request, status` (+ `input_request`, `input_settled` through `emit()` L107).
- Clean shutdown: `RunEvent::Exit` → `take()` + `block_on(shutdown())` = `kill()` of the sidecar (L1088-1098). **[GAP — packaging]**: only the generic mechanism is proved; Win/Mac triples matrix, bundle test, and proof of the missing-sidecar error in the UI not read. Risk: a force-quit with no `Exit` leaves the port alive **[GAP: port guard not implemented in the code read]**.

### 1.3. MSP protocol (audited state)

- `msp.rs`: `encode_request(id, method, params)` (L68-74, omits `params` if Null), `encode_notification` (L77-83, no `id`), `split_lines(buf, chunk)` (L86-99: accumulates partials, splits on `\n`, strips `\r`, ignores empty lines), `route_frame()` (L103-131: `id` → completes the pending `oneshot` (`result`/`error→RpcError{code,message,kind?,reason?,retryable?}`), `method` with no `id` → the `notify_tx` channel). The structured fields serve bounded decisions on the command side and are rendered as a short message; the raw JSON frame never leaves the bridge.
- `MspClient`: `child: SharedChild` (`Arc<Mutex<Option<CommandChild>>>` — `write` shares `&mut`, `kill` consumes), `next_id: AtomicU64` from 1, `pending: HashMap<String, Sender>`. `write_line()` appends `\n` then `child.write()`; `notify()` with no response; `request()` with a **120 s** timeout (`tokio::time::timeout`, L199) and `remove_pending` cleanup, typed errors ("sidecar write failed", "dropped the response", "timed out: {method}"). `shutdown()`: `take()` + `kill()` + `pending.clear()` (callers do not hang).
- Plain lifecycle MSP statuses are consumed in the live state; the renderer only adds to the log the events the user can act on (host stopped, turn rescheduled, queue removal, unreadable request). Unknown method names and payloads stay in the bounded diagnostics, never in the conversation.
- `new_command_id()` (L41-65): a UUIDv7 (48-bit unix-ms timestamp, version nibble 7, 74 random bits from `/dev/urandom` best-effort, variant `10`). MSP Rust tests: 10 tests cover frame shapes, partial framing, structured errors, out-of-order correlation, A/B isolation and a shutdown that wakes the callers. The bridge also adds framing and posture-fallback tests; `pump_stdout` reuses `ingest_stdout_chunk`, itself covered in the bridge's test module.
- **A contract verified from the bundled Windows binary** (stable `muse schema generate-ts`): `turn/start.input` is a non-empty list of `TurnInputPart` of the closed type `text|image|skill`. A `text` part carries `text`; an `image` part carries `mediaType` and `base64Data`, with `width`/`height` necessarily paired; file mentions stay text and the `mention` part is rejected. Methods/params not exercised live remain to qualify, but Muse can now send real images without inventing a file part.

### 1.4. Real-time transport (polling retained)

- What exists: **polling** over `EVENT_BUFFER_CAP = 2000` (`VecDeque<DrainedEvent{seq, session_id, kind, payload}>`, `event_seq: u64`, L81/95-96). `emit()` (L107-129) buffers + `pop_front()` beyond the cap. `poll_events(since: Option<u64>)` (L690-706): `since=None` → the head alone with no replay; otherwise `seq > since`. The comment at L77-80 and the hook at L304-306: the `listen` push was abandoned because "subscriptions resolved yet never fired" in one environment **[GAP: environment, repro, measurements absent]**. No raw frame log is enabled in production.
- Front end (`useMuseSessions.ts` + `poll.ts`): `POLL_FAST_MS=150` / `POLL_SLOW_MS=1000` (L70-71), an adaptive `setTimeout` loop on `runningRef` (L390-400, not `setInterval` — no stacking), a single serialised chain `PollChain{current}` + `enqueuePoll(chain.current.then(poll,poll))` (poll.ts L20-22): the periodic tick and `kickPoll()` after `send/answer/approve` share `cursorRef`, never two drains with the same cursor (otherwise duplicated text). Boot: an initial `poll_events{}` sets the cursor at the head (no history replay), then `tick()`. `aliveRef`/`cancelled` protect against StrictMode (double mount) and setState after unmount.
- Statuses derived from the kinds: `STOPPED_KINDS={cancelled, completed, stopped, exited, host_exited, error, turn_end, idle}`, `RUNNING_KINDS={started, running, created, turn_start}` (L122-134); `turn/*` → `running/stopped` through `mark_running()` + `emit("status",…)`.
- Target: push (`listen` repaired, or WebSocket/SSE) with a polling fallback. **[GAP]**: the caps (2000 events, 150/1000 ms, 120 s) have no load measurement; first instrument (firing rate, latency, CPU, drops), then decide (§7 M1).

### 1.5. Local persistence

- `persist.ts`: keys `muse-desktop.{sessions,workspace,active,tombstones}.v1` + `muse-desktop.log.v1.{sessionId}` (L36-40), with the defensive `storage.ts` facade. The other local registries (automations, notifications, index, memory, artifacts, imports, sharing, skills, browser, composer, theme and session settings) also use that facade; the `v1` keys and formats do not change. `StoredSession{session_id, workspace, title, createdAt}`, `LogEntry{id, ts, role:user|assistant|thinking|subagent|system|tool, text, agentId?, itemId?, open?}`. `MAX_LOG_ENTRIES=2000` (append-only, `slice(-2000)` on `appendLog`/`saveLog`), `MAX_TOMBSTONES=500` (`saveTombstones(ids.slice(-500))`). `loadLog` closes `open` blocks left open (new chunks → new entries). Invalid reads fall back with no exception and record a bounded diagnostic (`unavailable`, `corrupt`, `quota`); writes keep the previous value on failure. `SettingsPanel` offers local export and import of a JSON snapshot: entries are bounded to the `muse-desktop.*` namespace, existing keys are kept by default and replacement requires a confirmation, then the normal boot rehydrates the sessions. No network or engine call is triggered by the import. Migrations from earlier versions and selective restore remain **[GAP]**.
- `useMuseSessions`: boot restores sessions/logs/workspace/activeId (sessions marked `running:false` — children do not survive a restart), filters tombstones; write-through (`saveSessions` without `running`, `saveActiveId`, `saveWorkspace` except `null`); `killSession` → tombstone + `dropLog` + purging approvals/inputs + reassigning activeId. After `resume_session`, `read_session_history` requests an inline `session/read` and `history.ts` merges the folded items by `itemId` (or user text for old local echoes), keeps local notes and replaces partial streamed blocks with their durable state. When the host answers `methodNotFound`, the hook then walks `view/page` by cursor within a strict limit and folds item events by revision before the same merge; cursors stay opaque and no housekeeping event enters the transcript. The optional `session_durability` metadata comes from `initialize.sessionDurability` and is persisted with the session; when its value is `ephemeral`, the renderer keeps the transcript but offers no reconnection after a restart, because the host cannot resume that identifier. Absent values stay compatible with old rows and with hosts that do not declare that capability; a new successful handshake with no field clears the previous host observation for the workspace. `session/read`/`session/resume` `methodNotFound` errors are rendered as a durable-resume limitation, with the local transcript kept.
- Requirement (the Codex #22053/#18693 lesson): quotas + list virtualisation, never an unbounded log — already held by the 2000/500 caps.

### 2.3. Sidecar → UI events (`route_notification`, `main.rs:371-543`)

`item/started` → records `item_kinds[(sessionId,itemId)] = kind` (default `agentMessage`); `item/delta{itemId,delta}` → the lane by recorded kind: `subagent|workflow|reminderChild` → `emit(subagent_event,{agent_id:itemId,text:delta})`, reasoning/thinking/analysis and variants → `emit(thinking,{itemId,text:delta})`, `userShell` → `emit(shell_output,{itemId,text:delta})`, otherwise → `emit(output,{itemId,text:delta})`; `item/completed` → `emit(status,item_done,{itemId})` (extracts `item.itemId‖item.id‖itemId`, `""` otherwise). `item/updated` is a non-terminal update while `item.status == "inProgress"`: the bridge then extracts the bounded text and emits `item_updated{itemId,itemKind,lane,text,revision,turnId}` to replace the existing lane idempotently, without closing the lane; it only closes if its status becomes terminal. If a complete terminal item is received with no delta (a reconnection case, or a coalescing host), the bridge emits `item_started` once then its bounded output in the lane matching its kind before `item_done`; deltas already seen are never replayed. `approval/requested` → stores `PendingApproval{session_id, requirement_id:currentRequirementId}` under `approvalId`, payload `{request_id‖approvalId, toolName, summary:"{tool}: {rawArgs≤200}", choices[{choiceId,label,decision,scope}], itemId}` → `tool_request`; `approval/updated` → replaces the choices and the `currentRequirementId` of the same `approvalId`, emits `tool_request{updated:true}` without closing the resume block; `approval/resolved` → removes the token, `emit(status,{approvalId,decision,terminal:true})`; `turn/started` → `status:started`; `turn/completed` → `mark_running(false)` + `status:{terminal‖completed}` (+`reason`/`error.message`); `turn/retracted|unqueued|retryScheduled` → status as is; `userInput/requested` → `build_input_request_payload()` (questions `.take(10)`, options `.take(20)`, `single|multiple` modes only, `None` → `status:input_requested(unparseable)`) then `input_request`; `userInput/settled` → `input_settled{inputId,outcome}`; unknown ones ignored (additive schema). `pump_stdout` (L281-329): `split_lines` over stdout → `ingest` (or `unparseable frame` in stderr_tail), stderr → a 20-line tail, `Terminated` → `mark_running(false)` + `host_exited` to every known session.
`session/branchChanged` is a durable observation from the host: Muse keeps the known Git branch on the conversation row, persists it locally and shows it in the header. An absent value or a detached HEAD clears the old value; the renderer never infers a branch from the selected folder.

Rendering (`useMuseSessions.handleEvent`, L468-609): `output` → `parseChunk` (`{itemId,text}` JSON or plain text, never throws) coalesced into the **last open `assistant` entry** (`lastOpenIndex`, L188-198 — not the last raw entry, so as not to fragment on subagent/tool interleaving); `subagent_event` → `parseSubagent` (JSON `agent_id|id|name` + `text|chunk|output`, or `/*id*/ text`, or `id: text`, otherwise `agent`) grouped by open `agentId`; `input_request` → `parseInputRequest` (null → a system line); `input_settled` → removes the panel + a system line; `item_done` → `closeOpenBlocks(itemId?)` (with an id: only that block; without: all); `tool_request` → `parseApproval` (deduplicated by `request_id`, + a `tool` line, closes the blocks); others → liveness + a `[kind] payload` system line, closes the blocks.
