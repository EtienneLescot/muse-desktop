# Accessibilité native — M0-12 (20 septembre 2026)

Sonde CDP sur l'application réelle, sidecar Muse Windows natif 1.3.0, commit `main` après fusion de #161.
Ces mesures portent sur **Windows/WebView2** uniquement.

## Mode opératoire

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9222"
npm run tauri -- dev
node scripts/cdp-a11y-probe.mjs
node scripts/cdp-focus-pixels.mjs --out <dossier>
```

## 1. Ordre de tabulation effective

24 pressions de `Tab` via `Input.dispatchKeyEvent` (vraies frappes, pas des événements synthétiques), `document.activeElement` relevé après chaque.

| Mesure | Résultat |
|---|---|
| Arrêts | **24** |
| Arrêts distincts | **24** — aucun piège de focus, aucune boucle |
| Ordre | logical : `Latest messages` → **compositeur** → `Start voice input` → mode d'autorisation → effort de raisonnement → `Model settings` → `Skip to message input` → `Collapse sidebar` → navigation → sidebar |
| Sans indicateur visible | **1** — le `TEXTAREA` lui-même (voir §3) |
| Portant `aria-keyshortcuts` | 1 — `DIV.stream` avec **`Home End PageUp PageDown`** |

L'ordre suit le DOM de façon cohérente : contenu de conversation d'abord, puis navigation, puis liste des conversations. Aucun élément non interactif n'est atteint.

## 2. Raccourci Ctrl+F

| Mesure | Résultat |
|---|---|
| État avant | finder **visible** (`Find in conversation` présent dans le corps) |
| Après `Ctrl+F` | finder **fermé**, focus déplacé sur un champ de recherche |
| `placeholder` du champ focalisé | **`Search messages…`** |
| `aria-label` du champ focalisé | **`Search messages`** |

**Établi :** `Ctrl+F` est bien câblé et **bascule** le finder ; le focus part sur le champ de recherche, qui porte un libellé accessible. Le finder étant ouvert avant la mesure, l'effet observé est une fermeture : le test prouve la liaison du raccourci, pas son ouverture depuis un état fermé.

## 3. Indicateur de focus — faux positif corrigé

Première mesure : un cadrage étroit **autour du seul `TEXTAREA`** donnait deux captures au **SHA-256 identique**, ce qui suggérait l'absence de tout indicateur de focus. Les styles calculés confirmaient cette lecture (`outline: none 0px`, `box-shadow: none` sur le textarea **et** sur `.composer-main`, y compris avec `:focus-visible` actif).

**Cette conclusion était fausse.** Le champ est transparent et sans bordure : l'indicateur est dessiné sur le **conteneur** `.composer`, hors du cadrage initial. En élargissant la région au pied de page complet :

| Cadrage | Sans focus | Avec focus | Identiques |
|---|---|---|---|
| Étroit (textarea seul) | `8ef73afb…` | `8ef73afb…` | **oui** — mesure invalide |
| Large (pied de page) | `b6e715c1…` | `1d17edba…` | **non** |

La capture large montre un **anneau bleu** autour du compositeur lorsque le champ a le focus.

**Établi :** le compositeur **présente un indicateur de focus visible**. **Correction méthodologique à retenir :** mesurer le focus d'un champ transparent impose de cadrer son conteneur, pas le champ — sinon on conclut à tort à une absence.

*Réserve :* la capture large recadre le haut du compositeur et l'anneau y est tronqué. Les deux images seront recadrées plus large pour une preuve complète.

## 4. Contraste des textes

Calcul dans la page, sur les couleurs réellement appliquées : luminance relative WCAG, seuil 4,5:1 (texte normal) ou 3:1 (grand texte ≥ 24 px, ou ≥ 18,66 px en gras).

| Mesure | Résultat |
|---|---|
| Textes échantillonnés | **60** |
| En échec | **0** |
| Pires ratios | aucun — la liste des échecs est vide |

**Établi :** tous les textes visibles mesurés respectent **WCAG AA** sur les surfaces inspectées, en thème sombre.

## Ce qui reste ouvert pour M0-12

- **Lecteur d'écran réel** : non exercé. Aucun lecteur d'écran n'a été piloté ; les rôles et libellés accessibles observés (`aria-label`, `aria-keyshortcuts`, `placeholder`) sont une condition nécessaire, pas une preuve d'annonce correcte.
- **`forced-colors` / contraste élevé Windows** : non exercé. Le thème sombre a été mesuré, pas le mode contraste forcé.
- **Parcours complet sans souris** : 24 arrêts relevés, mais le parcours n'a pas été mené à terme sur un scénario réel.
- **macOS / Linux** : hors périmètre de cette passe.

**M0-12 n'est donc pas clos.** Trois de ses quatre critères ont maintenant des mesures natives ; le lecteur d'écran et le contraste forcé restent sans preuve.
