# Bounded transcript window over 2,000 entries — M1-13 (20 September 2026)

Native measurement in the webview, over CDP, on the native Windows Muse sidecar 1.3.0.

## Procedure

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9222"
npm run tauri -- dev
node scripts/cdp-long-transcript.mjs --entries 2000
```

The script first captures the original value of the target `muse-desktop.log.v1.<sessionId>` key, writes a 2,000-entry log in the **actually persisted format** (`{clientMessageId, id, role, text, ts}`), reloads the page so startup hydration reads the new log, measures, then **restores the original value** in a `finally` block.

## Result

| Measurement | Value |
|---|---|
| Entries written | **2,000** (+ 1 seed entry kept) |
| Target log | `muse-desktop.log.v1.01a0bea1…` (21,205 bytes → 347,671 bytes) |
| `data-entry-count` | **2001** |
| `data-window-start` / `data-window-end` | **0 / 160** |
| **Articles mounted in the DOM** | **160** |
| Log DOM nodes (including the 160 articles) | **967** |
| First article's `aria-setsize` | **2001** |
| First article's `aria-posinset` | **1** |
| The log's `aria-label` / `aria-keyshortcuts` | `Conversation messages` / `Home End PageUp PageDown` |
| `Load older messages` | absent — consistent, the window is already at index 0, hence already on the most recent messages |
| `Latest messages` present | yes |
| `Find in conversation` present | yes |

**Established:** on a 2,001-entry transcript, the application mounts only **160 articles** — exactly the bound documented in the roadmap ("a window of 160 messages"). The real total is exposed to assistive technologies through `aria-setsize`, and the global position through `aria-posinset`: the bounded window therefore does not degrade the semantic information.

The DOM cost stays contained: **967 nodes** for the whole log, articles included.

**Log restored**: the original value (21,205 bytes, 25 entries) was rewritten and verified after the measurement.

## Incremental loading of older messages — measured

```powershell
node scripts/cdp-scroll-window.mjs --entries 2000
```

The script writes 2,000 entries, reloads, then sets `scrollTop` to 0 — which triggers `onScroll` and its call to `loadOlderMessages()` as soon as `scrollTop < 120` — before actioning the **Load older messages** button by a second path.

| Step | DOM window | Articles mounted | First `posinset` | `scrollHeight` | Nodes |
|---|---|---|---|---|---|
| initial | **1840 – 2000** | **160** | 1841 | 174,694 | 970 |
| scroll 1 | **1720 – 1880** | **160** | 1721 | 165,478 | 971 |
| scroll 2 | **1600 – 1760** | **160** | 1601 | 156,238 | 971 |
| scroll 3 | **1480 – 1640** | **160** | 1481 | 146,998 | 971 |
| after the button | **1360 – 1520** | **160** | 1361 | 137,758 | 971 |

**Established:**

- the window **steps back 120 entries per load** — exactly the documented constant ("120 messages loaded on demand");
- the number of articles mounted **stays at 160** throughout the sequence: the DOM **does not grow** with successive loads;
- `aria-posinset` follows the window (1841 → 1361): the global position stays exact for assistive technologies;
- `scrollHeight` **decreases** at each step (174,694 → 137,758), the signature of virtual-spacer compensation — the content above stays represented, its height recomputed;
- the **Load older messages** button stays present while entries remain above.

Both paths — **scroll** and **button** — produce the same effect.

## What these measurements still do not cover

- **The finder jumping to a result outside the window**: `Find in conversation` is present in the DOM, but the jump to a result outside the window was not exercised over these 2,000 entries.
- **Performance** (rendering time, memory): not measured. The roadmap conditions full virtualisation on "a real measurement of memory and rendering time" — these documents do not replace it.
- **Native assistive qualification**: not exercised.
- macOS / Linux: out of scope.

**M1-13 is therefore not closed**, but its measurement criterion is now covered for the **DOM bound** *and* for **incremental loading**.
