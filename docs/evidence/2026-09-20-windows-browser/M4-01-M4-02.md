# Built-in browser evidence — M4-01 / M4-02 (20 September 2026)

CDP campaign on the development build, native Windows Muse sidecar 1.3.0.
Complements the [`2026-09-20-windows-group1`](../2026-09-20-windows-group1/README.md) report.

## Procedure

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9222"
npm run tauri -- dev
node scripts/cdp-panel.mjs https://example.com/
```

## The point that was blocking

Round 6 detected no tabs and concluded the work bar was unreachable. The measurement was redone on **an open and established conversation**, and the seven tabs are then present in the DOM:

**Content · Review · Terminal · Files · Browser · Desktop · Memory**

**Exact condition measured:** an open and **established** conversation, side panel in whatever state the previous session left it (not opened by the script during this measurement). What separates the two measurements is therefore **not** the panel's state — round 6's conclusion invoking a folded panel was a hypothesis, not a finding. The observed difference is the conversation's state: in round 6's run, the conversation had just been created and was in a connection error, with no work bar rendered.

**What stays undetermined:** whether the tabs also exist when the conversation is in a connection error and the panel is folded. The two variables were not isolated.

## M4-01 — built-in browser

| Control | Observation |
|---|---|
| Address field | `<input type="url">`, placeholder `https://example.com` |
| Navigation | URL set through the native setter, submitted by form (`typed: true, via: form`) |
| **Rendering** | **an `iframe` is mounted with `src: https://example.com/`** |
| Persistence | `muse-desktop.browser.tabs.v1.session.b7c2faf4` → `[{"id":"tab-b2b3bd24-…","url":"https://example.com/","history":["https://example.com/"],"historyIndex":0}]` |
| **Per-session isolation** | two distinct keys coexist: `…session.b7c2faf4` (navigated) and `…session.84bb6c78` (`url: ""`, `historyIndex: -1`). **No crossing between conversations.** |
| Controls available | **Open native**, **Reload**, **Save selected link**, **Observe page**, **Capture visible**, new tab button (`+`) |

**M4-01 conclusion:** navigation, per-tab persistence and isolation by `sessionId` are **proved in the native webview**. The "cross-platform native qualification" criterion stays open (Windows only observed), as do downloads initiated by navigation, which are not part of this pass.

## M4-02 — annotation

The annotation interface is **present and reachable** in the Browser panel:

- `Text for selected field` (typing into a field on the page);
- `Quoted selection (optional)` (quoting the selection);
- `Comment (required)` (the comment);
- actions **Add comment**, **Add page context**, **Observe page**, **Capture visible page**, **Click selected element**, **Navigate selected link**, **Open in new tab**, **Type into field**, **Save selected link**.

### An annotation actually created

Through `scripts/cdp-annotate.mjs`, an annotation was written then saved by the **Add comment** action. The persistent state went from `[]` to:

```json
[{"id":"3f629fe9-99f4-44ec-bf36-055bc78dea0c",
  "url":"https://example.com/",
  "selection":"example.com",
  "comment":"CDP annotation probe",
  "createdAt":1789907529662}]
```

**Established:** creating an annotation from the webview, with a **normalised URL anchor** (`https://example.com/`), preservation of the **selection quote** and the **comment**, a unique identifier and a timestamp. The persistence survives in `muse-desktop.browser.annotations.v1`.

### Context guard after navigation — proved

Two annotations are anchored on `https://example.com/`. The active tab was then navigated to **another domain**, `https://www.iana.org/help/example-domains`, and the state was recorded before and after:

| Moment | Active tab's URL | `iframe` mounted | Visible mentions of the notes | Persisted annotations |
|---|---|---|---|---|
| Before | `https://example.com/` | `https://example.com/` | **2** | 2 — URLs `https://example.com/` |
| After navigation | `https://www.iana.org/help/example-domains` | `https://www.iana.org/help/example-domains` | **0** | 2 — URLs still `https://example.com/` |

The tab's history became `["https://example.com/", "https://www.iana.org/help/example-domains"]` with `historyIndex: 1`.

**Conclusion:** a note anchored to a page **does not leak** to another. The annotations stay persisted with their original anchor and stop being shown as soon as the page changes. That is exactly the context guard M4-02 expects.

**Not established:** region cropping and visual capture of the page.

## Side panel label

The button that folds the panel is labelled **"Hide work panel"** in the DOM (not merely an icon name). That is the label to target for driving the panel reliably; the heuristic based on an icon with no accessible name must stay a fallback, since it can trigger unrelated actions.

## Side finding — refused capabilities

The end of the page body exposes an inventory of refused permissions: `browser denied`, `Allow finder denied`, `Allow terminal denied`, `Allow editor denied`, `Allow app`, along with the message:

> **Image generation is not available in the in-app browser — it views pages and anchors comments only.**

That is direct confirmation of the M0-13 policy ("clearly identify capabilities that are not connected"): the panel states its real scope itself instead of simulating it.

The transcript also exposes sub-agent control labels — `subagent/interrupt`, `subagent/stop`, `subagent/resume`, `subagent/followupTask`, `subagent/readResult` — along with `session/read`, which documents the surface actually wired.
