# Muse-Desktop 0.5.0 — macOS Apple Silicon, Windows x64

**On Windows, MuDesktop no longer includes the Muse engine.** It uses the Muse Code you install with
Meta's official installer, as on macOS. Nothing changes on macOS.

The app holds no agent logic. It drives the `muse` engine, which stays the only source of
authentication, models and tools. MuDesktop is an independent app for Muse Code; it is not made,
endorsed or supported by Meta.

## Changed on Windows

- **Install Muse Code with Meta's installer.** In PowerShell:

  ```powershell
  irm https://dev.meta.ai/install.ps1 | iex
  ```

  Then, in a new terminal, run `muse login` to sign in. MuDesktop uses the engine this installer
  puts in `%LOCALAPPDATA%\Programs\muse`.
- **The app guides you on first launch.** If Muse Code is missing, MuDesktop shows the command above
  with a Copy button, then `muse login`, and a *Check again* button. It does not run the installer
  itself.
- **Engine updates come from Muse itself.** MuDesktop never updates the engine: run `muse` in a
  terminal and Meta's launcher updates it. The app picks up the new version at its next start.
- **No more WSL check.** The environment check in Settings runs the installed engine's `--version`.

If you used 0.4.2 or 0.4.3 from the Microsoft Store, the copy of the old bundled engine in
`~\.local\share\muse-desktop\engine\` (about 440 MB) is no longer used and can be deleted.

Platforms, requirements and known limits are otherwise as in [0.4.0](0.4.0.md); on Windows the engine
row now reads "Muse Code, installed with Meta's installer".

## Verifying the package

The SHA-256 checksum of the Windows installer is published in
`Muse-Desktop_0.5.0_x64-setup.manifest.json`, next to the installer; it lists no engine. The macOS
DMG is verifiable through its Apple signature:

```sh
spctl -a -t open --context context:primary-signature -vv Muse-Desktop_0.5.0_aarch64.dmg
```
