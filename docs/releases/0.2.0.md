# Muse-Desktop 0.2.0 — Windows x64, macOS Apple Silicon

This increment finishes the computer-use story on Windows and opens two new doors: the agent can
now drive the browser you already use — with a dedicated consent — conversations can be shared
through a service **you** host, and work can run on another host over the SSH you already have.

The app holds no agent logic. It drives the `muse` engine, which stays the only source of
authentication, models and tools.

## New since 0.1.0

- **Drive your browser (with consent).** A dedicated *Attach the user's browser* switch in Settings
  (off by default) lets the agent inspect and drive the Edge/Chrome windows you already have open,
  signed-in profile included. The grant is enforced by the driver itself, and the app's tool ceiling
  keeps applying on top. Proved end to end on Windows: bind, read, click, an unexpected navigation
  observed and reported, and a decoy tab left untouched.
- **Share conversations to your own service.** Muse publishes a bounded, redacted bundle to a share
  service you run (LAN, VPS, NAS) — no account, no identity layer. A reference server ships with the
  repository (`node scripts/share-server.mjs`): a token gates publishing and revocation, reading
  needs nothing, links expire, and revocation is observable from any client (the same 404). Proved
  end to end from the app's Settings against that server.
- **Remote work over your SSH.** A new transport runs commands on another host through the system
  `ssh` binary — your existing keys and agent, no crypto added to the app. Fields are validated and
  the argv is built app-side; outputs are bounded and calls time out.
- **Under the hood.** The computer-use relay now surfaces the browser binding ids the model needs,
  and answers out-of-level tool calls itself when the driver runs without a capability manifest.

## Install

**macOS (Apple Silicon).** Open the DMG, drag the app into Applications. The app offers to install
the Muse CLI on first launch if you do not have it. Then choose a working folder.

**Windows (x64).** Run the installer. Windows will warn that the publisher is unknown: *More info*,
then *Run anyway*. It installs per-user into `%LOCALAPPDATA%\Muse-Desktop`, over a previous version
if there is one, with no administrator rights. Then choose a working folder.

## Requirements

- macOS 11 or later, Apple Silicon. No Intel build.
- Windows 10 or 11 x64, with WSL and Muse Code already set up in the default distribution, and
  WebView2 (shipped with Windows 11).
- A Muse Code account. Authentication and model choice come from the engine, not from this app.
- For computer use, the cua driver (MIT), installable from Settings.
- For sharing, a place to run the reference server (any machine with Node).

## Known limits

- The Windows installer is not signed, so SmartScreen warns on first launch.
- Windows is not self-contained: the engine lives in WSL, which must already be installed and
  authenticated. Projects must be reachable from the WSL distribution, and tool output paths stay
  Linux paths.
- No automatic updates. A new version installs over the old one without data loss.
- No Intel and no Linux build.
- Browser attach runs the driver in its standard permission mode: process termination stays off,
  and the grant lasts until you turn it off. Edge's own remote-debugging consent is a one-time,
  per-install approval.
- Sharing goes to a service you host; nothing is published until you configure it, and nothing
  leaves your machine without that configuration.
- Remote SSH execution needs a reachable host; a refused connection is the measured proof the
  transport drives the binary, not that any host accepts it.
- Open defects tracked in the [roadmap](../ROADMAP.md).

## Reporting a problem

Say what you were doing, what you expected, and what happened. App data lives under
`com.muse.desktop`: in `~/Library/Application Support/` on macOS, in `%APPDATA%` on Windows.

## Verifying the package

SHA-256 checksums for the Windows installer and the engine it bundles are published in
`Muse-Desktop_0.2.0_x64-setup.manifest.json`, next to the installer. The macOS DMG is verifiable
through its Apple signature:

```sh
spctl -a -t open --context context:primary-signature -vv Muse-Desktop_0.2.0_aarch64.dmg
```
