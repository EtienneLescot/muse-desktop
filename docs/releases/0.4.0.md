# Muse-Desktop 0.4.0 — macOS Apple Silicon, Windows x64

This release qualifies macOS. **35 of 53 tickets are proved on macOS**, each on the real app with a
reproducible native proof, against the same engine as Windows, Muse 1.4.2. Windows stays at 43 ☑.
It also fixes the defects that campaign found, three of them on shared code that could weaken
security or lose work.

The app holds no agent logic. It drives the `muse` engine, which stays the only source of
authentication, models and tools.

## New since 0.3.0

- **Safer worktree removal.** *Force remove* on a worktree with uncommitted changes now asks first,
  and a worktree a conversation runs in can no longer be removed from under it.
- **A project's isolation holds on restart.** *Restart workspace host* finds the project of a folder
  even when it is spelled through a symbolic link (`/var` and `/private/var` on macOS), so a Read
  only project no longer restarts at the global level.
- **The terminal on macOS.**
  - Shells start in UTF-8 when the app is launched from the Finder or the Dock.
  - Typed quotes and dashes reach the shell as typed.
  - A character split between two reads of the terminal is no longer replaced.
- **Code typed into the composer** keeps its straight quotes and `--`; macOS no longer substitutes
  them.
- **Files** shows the first entries of a large folder in display order on every file system.
- **Worktree setup**: *Cancel* and the ten-minute limit stop the whole command, not only its shell.
- **Zoom** (Cmd+Plus, Cmd+Minus, Cmd+0) works, and the conversation switch is shown as Ctrl+Tab, the
  key that does it.
- **Settings** states that on macOS, *Workspace only* lets commands write in the system's temporary
  folders.
- **For contributors**: native macOS proofs and the end-to-end check run on WKWebView through an
  isolated test mode compiled into debug builds only (ADR 0003, amended).

## Platforms

| | macOS | Windows |
|---|---|---|
| Package | DMG, Apple Silicon | NSIS installer, x64 |
| Signature | Developer ID signed and notarised | **Unsigned**, SmartScreen warning |
| Engine | Muse CLI, installed by the app on first launch into `~/.local/bin/muse` | Muse 1.4.2, bundled |
| Rights | None | None, installs into `%LOCALAPPDATA%` |

Both platforms are **qualified natively**: Windows since 0.3.0, macOS in this release, on macOS 26.5
with Apple Silicon.

## Install

**macOS (Apple Silicon).** Open the DMG and drag the app into Applications, over a previous version
if there is one. The app offers to install the Muse CLI on first launch if you do not have it. Then
choose a working folder.

**Windows (x64).** Run the installer. Windows will warn that the publisher is unknown: *More info*,
then *Run anyway*. It installs per-user into `%LOCALAPPDATA%\Muse-Desktop`, over a previous version
if there is one, with no administrator rights. Then choose a working folder.

## Requirements

- macOS 11 or later, Apple Silicon. No Intel build.
- Windows 10 or 11 x64, with WebView2 (shipped with Windows 11).
- A Muse Code account. Authentication and model choice come from the engine, not from this app.
- For computer use, the cua driver (MIT), installable from Settings.

## Known limits

**On macOS**, eighteen tickets stay open: M4-10 (a self-hosted cloud runner) is not started on any
platform, and the seventeen others wait for a person, a permission, a machine, an engine fix or
shared code:
- **A person or a permission**: screen reader (M0-12, M1-13), Japanese and Chinese input methods
  (M0-03), voice (M4-08), notifications (M3-09), desktop computer use (M0-13, M4-04), the `launchd`
  wake-up with the app closed, sleep and lock (M3-06, M3-07), sharing from a second device (M4-06),
  first launch on a clean Mac (M0-10), the two-project scenario in the packaged app (M0-01).
- **The engine**: conversation branches from an earlier turn (M1-09, upstream #97 and #103).
- **Shared code, open on every platform**:
  - a worktree is left behind when its conversation fails to start (M2-03);
  - an interrupted cleanup is not resumed (M2-06);
  - sub-agent lanes cannot be stopped on Muse 1.4.2 (M2-07);
  - a DOCX attached to the composer is refused (M4-05).

**Engine behaviour on macOS 1.4.2:**
- *Run in Muse* (the user shell) needs *Elevated access*: under the sandbox the engine answers
  "managed shell sandbox is unavailable" (upstream #104).
- Under *Workspace only*, commands may write in `$TMPDIR` and `/tmp`, as Settings says.

**On Windows**, the limits of 0.3.0 still apply: the installer is not signed, and first launch on a
clean machine is not qualified.

Also:
- No automatic updates. A new version installs over the old one without data loss.
- No Intel and no Linux build.
- Deferred low items are listed in the [backlog](../plans/2026-10-13-backlog.md); none loses data
  or weakens security. Full state in the [roadmap](../ROADMAP.md).

## Reporting a problem

Say what you were doing, what you expected, and what happened. App data lives under
`com.muse.desktop`: in `~/Library/Application Support/` on macOS, in `%APPDATA%` on Windows.

## Verifying the package

SHA-256 checksums for the Windows installer and the engine it bundles are published in
`Muse-Desktop_0.4.0_x64-setup.manifest.json`, next to the installer. The macOS DMG is verifiable
through its Apple signature:

```sh
spctl -a -t open --context context:primary-signature -vv Muse-Desktop_0.4.0_aarch64.dmg
```
