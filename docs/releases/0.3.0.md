# Muse-Desktop 0.3.0 — Windows x64, macOS Apple Silicon

This release closes the Windows roadmap: **43 of 53 tickets are proved on Windows**, each on the
real app with a reproducible proof. It also carries everything prepared for 0.2.0, which was tagged
but never published.

The app holds no agent logic. It drives the `muse` engine, which stays the only source of
authentication, models and tools.

## New since 0.1.0

- **Engine 1.4.2.** The Windows installer now bundles Muse 1.4.2, the engine every Windows proof of
  this release ran on.
- **Approvals and questions survive incidents.** A pending approval or question can still be
  answered after a host restart; a retryable failed decision is sent again once.
- **The policy in force is the one shown.** A project follows the global isolation level of
  Settings unless its own preferences restrict it. The middle posture is renamed *Ask only for more
  access*.
- **Move work between Local and a worktree** within the same conversation, with a Git transfer that
  rolls back on failure.
- **Projects with several folders**, scheduled runs anchored to the turn that produced them, and a
  safer host lifecycle: a replaced or closed host keeps its conversation's events, and *Restart
  workspace host* warns the conversations it stops.
- **Remote engine over SSH.** A conversation can run on an engine reached through the system `ssh`
  binary, with your existing keys and agent.
- **Drive your browser (with consent).** An *Attach the user's browser* switch in Settings, off by
  default, lets the agent drive the Edge or Chrome windows you already have open.
- **Share conversations to your own service.** Muse publishes a bounded, redacted bundle to a share
  service you run. A reference server ships with the repository (`node scripts/share-server.mjs`).
- **Engine compatibility check.** The app recognises the engine it talks to and says so when it is
  not one it supports.

## Platforms

| | macOS | Windows |
|---|---|---|
| Package | DMG, Apple Silicon | NSIS installer, x64 |
| Signature | Developer ID signed and notarised | **Unsigned**, SmartScreen warning |
| Engine | Muse CLI, installed by the app on first launch into `~/.local/bin/muse` | Muse 1.4.2, bundled |
| Rights | None | None, installs into `%LOCALAPPDATA%` |

The 0.3.0 features are **qualified on Windows**. The macOS build is produced by the same pipeline
but has not had its own qualification campaign.

## Install

**macOS (Apple Silicon).** Open the DMG, drag the app into Applications. The app offers to install
the Muse CLI on first launch if you do not have it. Then choose a working folder.

**Windows (x64).** Run the installer. Windows will warn that the publisher is unknown: *More info*,
then *Run anyway*. It installs per-user into `%LOCALAPPDATA%\Muse-Desktop`, over a previous version
if there is one, with no administrator rights. Then choose a working folder.

## Requirements

- macOS 11 or later, Apple Silicon. No Intel build.
- Windows 10 or 11 x64, with WebView2 (shipped with Windows 11).
- A Muse Code account. Authentication and model choice come from the engine, not from this app.
- For computer use, the cua driver (MIT), installable from Settings.

## Known limits

- The Windows installer is not signed, so SmartScreen warns on first launch.
- **First launch on a clean Windows machine is not yet qualified** (M0-10). This release was proved
  on a machine where Muse was already set up and signed in.
- Nine tickets stay open on Windows, each waiting for a person, a machine or an engine fix rather
  than code: screen reader (M0-12, M1-13), voice (M4-08), sharing from a second device (M4-06),
  desktop computer use (M0-13, M4-04), sleep and clock changes (M3-07), clean-machine first launch
  (M0-10), conversation branches (M1-09, engine fix upstream).
- No automatic updates. A new version installs over the old one without data loss.
- No Intel and no Linux build.
- Deferred low items are listed in the [backlog](../plans/2026-10-06-backlog.md); none loses data
  or weakens security. Full state in the [roadmap](../ROADMAP.md).

## Reporting a problem

Say what you were doing, what you expected, and what happened. App data lives under
`com.muse.desktop`: in `~/Library/Application Support/` on macOS, in `%APPDATA%` on Windows.

## Verifying the package

SHA-256 checksums for the Windows installer and the engine it bundles are published in
`Muse-Desktop_0.3.0_x64-setup.manifest.json`, next to the installer. The macOS DMG is verifiable
through its Apple signature:

```sh
spctl -a -t open --context context:primary-signature -vv Muse-Desktop_0.3.0_aarch64.dmg
```
