# Muse-Desktop 0.4.2 — macOS Apple Silicon, Windows x64

A fix for the **Microsoft Store** build of MuDesktop. Nothing changes on macOS or for the Windows
installer from GitHub.

The app holds no agent logic. It drives the `muse` engine, which stays the only source of
authentication, models and tools. MuDesktop is an independent app for Muse Code; it is not made,
endorsed or supported by Meta.

## Fixed

- **Shell commands work in the Store build.** In 0.4.1 from the Microsoft Store, every command the
  agent ran (git included) failed: Muse's Windows sandbox relaunches the engine as a sandbox user and
  must grant that user access to the engine file, which Windows forbids inside the Store's install
  folder. The app now copies the engine once per version to `~\.local\share\muse-desktop\engine\`
  and runs it from there; the sandbox stays on. The copy takes about 440 MB, and older versions'
  copies are removed.
- **No coloured square behind the taskbar icon** in the Store build: the package now ships the
  "unplated" icon variants Windows uses in the taskbar and the Start menu's app list.

Platforms, requirements, known limits and verification are as in [0.4.0](0.4.0.md).

## Verifying the package

SHA-256 checksums for the Windows installer and the engine it bundles are published in
`Muse-Desktop_0.4.2_x64-setup.manifest.json`, next to the installer. The macOS DMG is verifiable
through its Apple signature:

```sh
spctl -a -t open --context context:primary-signature -vv Muse-Desktop_0.4.2_aarch64.dmg
```
