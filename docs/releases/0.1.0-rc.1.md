# Muse-Desktop 0.1.0-rc.1 — Windows x64, macOS Apple Silicon

Release candidate de la **première version stable**. Ces notes décrivent le produit entier, pas
seulement les changements depuis la beta 2 : c'est la première fois que Muse-Desktop est publié
comme une version finie plutôt que comme une beta.

Deux nouveautés majeures depuis la beta 2 : **macOS** est une plateforme supportée, et le **DMG
macOS est signé et notarisé par Apple** — plus d'avertissement Gatekeeper. L'installateur Windows
reste non signé.

## Ce qu'est Muse-Desktop

Une application de bureau pour travailler avec Muse Code : une fenêtre dédiée, des conversations
rangées par projet, et le fil de ce que fait le modèle rendu lisible. L'application **ne contient
aucune logique d'agent** — elle pilote le moteur `muse`, qui reste la seule source de
l'authentification, des modèles et des outils.

## Ce que l'application fait

**Conversations et projets.** Créer des conversations, les ranger par dossier de travail, les
renommer, les réordonner en les faisant glisser, en supprimer une ou toutes d'un coup. Tout est
retrouvé après fermeture et réouverture. Le dossier de travail est choisi par conversation, avec
héritage par projet. Au-delà de 32 conversations chargées — la limite du moteur — l'application
libère la place au lieu d'échouer, et reprend une conversation quand on l'ouvre.

**Le fil.** Les réponses sont rendues en Markdown (tableaux, blocs de code avec bouton Copier). La
phase de réflexion apparaît avant le premier mot de la réponse, dans un bloc repliable. Les appels
d'outils défilent en direct puis se replient en une ligne (« 12 steps · 49s »). Les sous-agents ont
leur propre piste, groupée et repliable. Un tour arrêté est marqué « Stopped » — sans faux signal
de reprise.

**Reprendre autrement.** Forker une conversation depuis un message précis, ou la conversation
entière depuis son menu.

**Approbations.** Trois postures, dans les Réglages : *Ask for approval* laisse chaque demande à
l'utilisateur, *Approve on my behalf* décide seul ce qui reste local au dossier de travail et
continue de demander pour le réseau et les élévations, *YOLO* accepte tout ce qui n'est pas refusé.
Une approbation est liée à sa session et à sa demande : un jeton périmé ou venu d'une autre
conversation est refusé, jamais appliqué en silence.

**Composeur.** Choix du modèle dès l'écran d'accueil, niveau d'effort aligné sur ceux de Muse,
indicateur d'utilisation du contexte (un clic compacte la conversation), et les skills accessibles
par `/`.

**Le panneau latéral.** *Changes* pour la revue des modifications, *Terminal* démarré dans le
dossier de la conversation, *Files*, et un *Browser* intégré avec onglets, navigation, barre
d'adresse et ouverture en fenêtre pour les sites qui refusent d'être intégrés.

**Worktrees.** Démarrer une conversation dans un worktree git, ou y déplacer une conversation
existante.

**Extensions et mémoire.** Des serveurs MCP distants se testent depuis *Extensions* avec une URL
HTTPS : l'application effectue un vrai échange `initialize`/`tools/list` avant d'enregistrer le
catalogue. Les jetons restent en mémoire et, dans la version desktop, dans le gestionnaire de
secrets du système (Trousseau macOS, Credential Manager Windows) pour une reconnexion explicite
après relance. La mémoire du projet se consulte et s'édite dans les Réglages.

**Utilisation de l'ordinateur.** Muse peut voir l'écran et, avec votre accord, piloter les
applications, via le driver open-source [CUA](https://github.com/trycua/cua). Deux niveaux dans les
Réglages : **Observe only** (captures et lecture des fenêtres) et **Observe and act** (souris,
clavier, presse-papiers). Le driver s'installe depuis l'application.

## Les deux plateformes

| | macOS | Windows |
|---|---|---|
| Paquet | DMG, Apple Silicon | Installateur NSIS, x64 |
| Signature | **Signé Developer ID et notarisé** | **Non signé** — avertissement SmartScreen |
| Moteur | Le CLI Muse, installé par l'application au premier lancement dans `~/.local/bin/muse` | Muse dans la distribution WSL par défaut, via un pont fourni avec l'installateur |
| Droits | Aucun | Aucun — installation dans `%LOCALAPPDATA%` |

## Installation

### macOS (Apple Silicon)

1. Ouvrir `Muse-Desktop_0.1.0-rc.1_aarch64.dmg` et glisser l'application dans *Applications*.
2. Le paquet étant notarisé, **aucun avertissement Gatekeeper** n'apparaît.
3. Au premier lancement, l'application propose d'installer le CLI Muse si vous ne l'avez pas.
4. Choisir un dossier de travail.

### Windows (x64)

1. Lancer `Muse-Desktop_0.1.0-rc.1_x64-setup.exe`.
2. **Windows affichera un avertissement** — l'installateur n'est pas signé. Pour continuer :
   « Informations complémentaires » puis « Exécuter quand même ».
3. L'installation se fait dans `%LOCALAPPDATA%\Muse-Desktop`, par-dessus une version précédente le
   cas échéant, et ne demande **aucun droit administrateur**.
4. Choisir un dossier de travail.

## Configuration requise

- **macOS 11 ou plus récent, Apple Silicon.** Pas de version Intel.
- **Windows 10 ou 11, x64**, avec **WSL et Muse Code déjà configurés** dans la distribution par
  défaut, et WebView2 (fourni avec Windows 11).
- **Un compte Muse Code** : l'authentification et le choix du modèle viennent du moteur, pas de
  cette application.
- Pour l'utilisation de l'ordinateur : **cua-driver** (MIT), installable depuis les Réglages.

## Limites connues

- **L'installateur Windows n'est pas signé** : avertissement SmartScreen au premier lancement. Le
  DMG macOS, lui, est signé et notarisé.
- **Windows n'est pas autonome** : le moteur vit dans WSL, qui doit déjà être installé et
  authentifié. Les projets Windows doivent être accessibles à la distribution WSL, et les chemins
  de sortie des outils restent des chemins Linux.
- **Pas de mise à jour automatique** : une nouvelle version s'installe par-dessus l'ancienne, sans
  perte de données.
- **Intel et Linux ne sont pas livrés.**
- **« Observe and act » n'a pas de garde-fou côté driver** : votre accord dans les Réglages est la
  seule barrière. N'activez ce niveau que le temps nécessaire.
- **Défauts connus non corrigés**, relevés par la campagne de qualification native et suivis dans
  la [roadmap](../ROADMAP.md) : sortie vide du terminal PTY dans certains cas, étiquette de modèle
  partagée entre deux fils, worktree créé mais non utilisé par la conversation, et sandbox shell
  indisponible pour un moteur lancé par l'application.
- **Accessibilité** : le balisage et la navigation clavier sont vérifiés ; l'application n'a **pas**
  été testée avec un lecteur d'écran réel.

## Rapporter un problème

Décrivez ce que vous faisiez, ce que vous attendiez, et ce qui s'est produit. Les données de
l'application sont rangées sous `com.muse.desktop` : dans `~/Library/Application Support/` sous
macOS, dans `%APPDATA%` sous Windows.

## Vérifier le paquet

Les sommes de contrôle SHA-256 de l'installateur Windows et du moteur qu'il embarque sont publiées
dans `Muse-Desktop_0.1.0-rc.1_x64-setup.manifest.json`, à côté de l'installateur. Le DMG macOS est
vérifiable par sa signature Apple :

```sh
spctl -a -t open --context context:primary-signature -vv Muse-Desktop_0.1.0-rc.1_aarch64.dmg
```
