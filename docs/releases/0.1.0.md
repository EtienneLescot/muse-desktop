# Muse-Desktop 0.1.0 — Windows x64, macOS Apple Silicon

Muse Code ships as a CLI. This is the desktop app that goes with it: conversations organised by
project, the agent's work readable as it happens, and an opt-in switch that lets it see your screen
and use your applications.

The app holds no agent logic. It drives the `muse` engine, which stays the only source of
authentication, models and tools.

## New since beta 2

- **macOS is a supported platform**, and the DMG is signed and notarised by Apple, so there is no
  Gatekeeper warning. The Windows installer is still unsigned.

## What it does

- **Projects and conversations.** A project is a folder. Conversations are grouped under the folder
  they run in, renameable, reorderable by drag, and they survive a restart. Past the engine's limit
  of 32 loaded conversations, the app makes room instead of failing and resumes one when you open it.
- **A readable thread.** Markdown answers with tables and copyable code blocks. Thinking appears
  before the first word of the answer, in a block you can fold away. Tool calls stream live, then
  collapse into one line. Sub-agents get their own lane. A stopped turn is marked as stopped.
- **Computer use.** Muse can look at your screen and, with your consent, drive your applications,
  through the open-source [cua driver](https://github.com/trycua/cua) (MIT). Two levels in Settings:
  *Observe only* (screenshots and window reading) and *Observe and act* (mouse, keyboard, clipboard).
  Off by default, revocable at any moment, and the grant is a list of named tools. The driver
  installs from the app.
- **Approvals.** Three postures: ask every time, approve what stays inside the working folder, or
  let it run. An approval is bound to the conversation that asked for it, so a stale one is refused
  rather than silently applied.
- **Branching.** Fork a conversation from any turn, or continue it in a git worktree while your
  folder stays untouched.
- **The tools next to the work.** A diff review panel, a terminal that opens in the conversation's
  folder, a file tree, and a browser with tabs.
- **Your own tools.** Remote MCP servers are verified with a real `initialize`/`tools/list`
  handshake before the catalogue is saved; tokens go to the system keychain. Skills from the host and
  from your workspace are offered as you type `/`.
- **Composer.** Model choice from the welcome screen, reasoning effort, and a context meter that
  compacts the conversation in one click.

## Install

**macOS (Apple Silicon).** Open the DMG, drag the app into Applications. The app offers to install
the Muse CLI on first launch if you do not have it. Then choose a working folder.

**Windows (x64).** Run the installer. Windows will warn that the publisher is unknown: *More info*,
then *Run anyway*. It installs per-user into `%LOCALAPPDATA%\Muse-Desktop`, over a previous version
if there is one, with no administrator rights. Then choose a working folder.

## Requirements

- macOS 11 or later, Apple Silicon. No Intel build.
- Windows 10 or 11 x64, with WSL and Muse Code already set up in the default distribution, and
  WebView2 (shipped with Windows 11).
- A Muse Code account. Authentication and model choice come from the engine, not from this app.
- For computer use, the cua driver (MIT), installable from Settings.

## Known limits

- The Windows installer is not signed, so SmartScreen warns on first launch.
- Windows is not self-contained: the engine lives in WSL, which must already be installed and
  authenticated. Projects must be reachable from the WSL distribution, and tool output paths stay
  Linux paths.
- No automatic updates. A new version installs over the old one without data loss.
- No Intel and no Linux build.
- *Observe and act* has no guard rail on the driver side. Your consent in Settings is the only
  barrier, so turn it on only for as long as you need it.
- Open defects tracked in the [roadmap](../ROADMAP.md): empty PTY terminal output in some cases, a
  model label shared between two threads, a worktree created but not used by the conversation, and
  the shell sandbox unavailable for an engine the app started.
- Accessibility: markup and keyboard navigation are checked. The app has not been tested with a real
  screen reader.

## Reporting a problem

Say what you were doing, what you expected, and what happened. App data lives under
`com.muse.desktop`: in `~/Library/Application Support/` on macOS, in `%APPDATA%` on Windows.

## Verifying the package

SHA-256 checksums for the Windows installer and the engine it bundles are published in
`Muse-Desktop_0.1.0_x64-setup.manifest.json`, next to the installer. The macOS DMG is verifiable
through its Apple signature:

```sh
spctl -a -t open --context context:primary-signature -vv Muse-Desktop_0.1.0_aarch64.dmg
```
